# AGENTS.md

NixOS flake + Home Manager config (hosts: grimoire, spellbook = laptops; tower = server),
synced across machines via git (pull → rebuild).

## Hard rules
- NEVER `git commit`/`push`/`amend` or alter history. Edit files, leave the tree dirty; the user reviews and commits — propose a commit message after changes.
- Never hand-edit `hosts/*/hardware-configuration.nix` (generated by `nixos-generate-config`) — regenerate instead.
- `system.stateVersion` / `home.stateVersion` are `25.11` — leave unchanged.

## Commands
- Apply: `sudo nixos-rebuild switch --flake ~/.config/nixos` (attr defaults to current hostname)
- Build only: `nixos-rebuild build --flake ~/.config/nixos`
- Eval check: `nix flake check` · list hosts: `nix eval .#nixosConfigurations --apply 'x: builtins.attrNames x'`
- Format: `nix fmt` (nixfmt, declared as flake formatter)
- Update inputs: `nix flake update [<input>] --flake ~/.config/nixos`
- Option lookup: https://search.nixos.org/options?channel=26.05 · https://home-manager-options.extranix.com/?release=release-26.05

## Architecture
- Inputs: `nixpkgs` = `nixos-26.05`, `home-manager` = `release-26.05` (follows nixpkgs), `nixpkgs-unstable` = `nixos-unstable` for newer versions of select packages; all inputs reach modules via `specialArgs`.
- `pkgs.unstable` is exposed to every module via an overlay in `flake.nix`; unstable uses the default config, so `nixpkgs.config` settings (e.g. `allowUnfree`) do not apply to it.
- `flake.nix` builds one `nixosConfiguration` per `hosts/*/` directory; Home Manager plumbing (`useGlobalPkgs`, `useUserPackages`, `backupFileExtension`, `extraSpecialArgs`) lives inline in `flake.nix` — `modules/` only takes effect via imports.

## Layout & placement
- `hosts/<name>/` — machine facts only (hostname, stateVersion, hardware). Compose bundles: `modules/shared` + `modules/laptop`|`modules/server` + needed `users/<name>`. Dir name must equal `networking.hostName`.
- `modules/<role>/` — library of config snippets; hosts import the role's `default.nix` bundle, never `modules/` wholesale. Each file exists exactly once. Modules may be machine-specific; only make one machine-agnostic once a second machine needs it.
- `users/<name>/` — everything per-user: `default.nix` (NixOS account), `keys/` (SSH pubkeys), `home/` (Home Manager). Hosts opt into the full HM config via `users.<name>.fullHome = true` (declared in that user's `default.nix`); without it only the system account is created.
- `shared/boot.nix` derives initrd LUKS entries (with `allowDiscards`) from the mounts/swap in `hardware-configuration.nix` (`luks-<uuid>` mapper convention); custom boot bits go in the host config.

## Conventions
- New system feature → module in the role dir that needs it + one line in that dir's `default.nix`.
- Packages for every host → `modules/shared/packages.nix`; anything behind `programs.<x>.enable`/`services.<x>.enable` → its own module.
- DE session bits → `shared/gnome.nix` / `laptop/noctalia.nix`; pipewire is enabled globally in `shared/pipewire.nix`, so DE modules add no audio config.
- Firewall ports in modules stay global (not interface-scoped) — LAN/WAN scoping is enforced upstream at opnsense.
- Run `nix fmt` on touched files.
- Commit messages: Conventional Commits (`feat:`, `fix:`, `chore:`, …), minimalist subject, no body unless it really earns it.
- Hand-over ready: never assume future hosts resemble current ones. A machine matching no existing role gets a new role dir under `modules/`.

## Gotchas
- grimoire ≡ spellbook: both = `shared` + `laptop` + `users/ruben` (fullHome on); only the hostname differs. tower = `shared` + `server` + `users/{ruben (lean home), gaming, camille}`; `printing.nix` is laptop-only, deliberately absent there.
- gnome↔noctalia transition is laptop-only — server stays gnome: both bundles active on laptops; if noctalia wins, `gnome.nix` moves `shared/ → server/`.
- `laptop/noctalia.nix` imports the noctalia/umbriel NixOS modules straight from the `nixpkgs-unstable` input tree (options don't exist in stable 26.05) and pins `pkgs.unstable` packages — follow that pattern when touching it.
- `modules/laptop/prometheus.nix`: node exporter intentionally disabled (pending kube-prometheus integration) — do not enable it or drop the 9100 firewall rule unprompted.
- `users/ruben/default.nix`: `extraGroups` lists feature groups unconditionally (undefined ones are silently dropped) — keep the plain list, do not add `lib.optionals`/`mkIf` guards.
- nvim lua is out-of-store-symlinked from this repo into `~/.config/nvim/lua`; `users/ruben/home/nvim/lua/matugen.lua` is generated at runtime by matugen and gitignored (nvim plugins conditionally enable on its existence) — don't create or track it.
- Machine-specific modules are fine: `server/{zfs,k3s,gnome-kiosk,unmanaged-nics}.nix` hardcode tower facts (pool `data` + hostId, `--data-dir=/data/crypt/k3s` + no autostart until `/data/crypt` is mounted, autologin as `gaming`, opnsense NIC names). `zfs.nix` also pins the default kernel, overriding boot.nix's latest-kernel default (ZFS needs it) — see their comments; a second server would mean generalizing these modules instead.
